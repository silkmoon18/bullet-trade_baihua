# 成交价格为 0：当前处理口径

本规则不区分 QMT 模拟账户和真实账户，也不改变正常有价成交、聚宽选股或 QMT 报价/追单。只有成交编号、委托关联、标的、方向和股数可靠时，才允许把缺价回报作为一笔已成交交易入账；缺失这些字段仍阻断对应异常，不能凭价格估算捏造成交。

## 缺价成交如何继续运行

1. **股数照实记**：更新委托已成交数量和策略持仓，重复回报只记一次，避免因为价格为 0 而重复下单。
2. **估算单价直接入账**：优先用提交目标时保存的标的参考价；其次用本地委托限价。两者都缺失时，买入按本单预留资金与剩余股数估价，卖出按已有持仓成本估价。买入估价不得超过本单可用预留资金。估价写入 `fills.price_units`，标记 `price_source=ZERO_PRICE_ESTIMATE`、`price_known=false`，原始回报价 0 与估算依据保留在成交分录中；不能冒充券商真实成交价。若连有效预留资金或持仓成本都没有，才保留历史零价降级路径，不凭空造价。
3. **其余成交路径不变**：按估算单价计算现金、持仓成本、已实现盈亏和目标执行；估算卖出回款可用于后续调仓。实际发单仍须通过券商可用资金等原有校验。重复回报不重复入账。
4. **收益明确标为非精确**：估算成交可以计算参考 NAV/收益，但 API 使用 `estimated_nav`、`estimated_returns` 并附 `returns_note=非精确收益…`；精确 `nav`、`returns` 仍为 `null`。飞书卡片的单价和金额注明“估算”，聚宽日志写明“非精确收益”。未知费用也使收益只能作为估算。

`ZERO_FALLBACK` 是统一的缺价处理策略，不是单独的模拟盘交易流程。部署时须显式配置 `QMT_STRATEGY_UNPRICED_FILL_POLICY=ZERO_FALLBACK`；默认 `STRICT` 仍拒绝缺价回报。券商若以后对同一成交 ID 返回可信价格，账本会校验交易身份并补正估算金额与成本；流程不依赖于这件事发生。已知佣金/税费照常计，未知费用仍标未知。

## 验收重点

- 零价买卖均使已成交数量、持仓与 QMT 回报一致，重复回报不重复入账或发单。
- 零价卖出后的暂估现金可继续调仓；零价买入按参考价或预留预算暂扣，剩余委托仍可继续。
- 真实价格成交路径不变；缺价时只展示注明“非精确收益”的估算指标，资金/总资产明确标为含暂估。
- 参考价超过买入预留时只压到已预留预算并标注，不因此拒绝已发生的成交；券商现金或持仓真的不足时，原有对账拦截仍然生效。
- 切换服务前备份整个 `.data`（含 SQLite、WAL/SHM）；不修改旧成交分录，不通过改策略 ID 绕过账本异常。
