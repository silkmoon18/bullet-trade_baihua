# GoodETF 重新起账与切换 QMT 资金账户

`STRATEGY_ID` 是一套持续的策略账本身份，不是“清零”按钮。账本里还保存了资金分配、委托、成交、持仓、收益和幂等键。只改 ID 会新建另一个账本，旧账本占用的资金不会自动退回；只改 QMT 登录账号则可能把旧账错用到新账号。服务器现在会校验账本绑定的物理 QMT 账号，发现变化就拒绝继续使用。

## 同一模拟账户重新开始

1. 先关闭服务器策略交易和大 QMT 桥接写权限；确认旧策略不再发单、没有活动委托。不要在有未完成订单时重启账本。
2. 备份完整 `.data`（包含 SQLite 数据库及可能存在的 `-wal`/`-shm` 文件）和私有配置。保留旧账本供审计，绝不直接删某个策略的 SQL 行。
3. 核对 QMT 当前物理持仓。`unassigned_broker_positions` 只表示物理持仓超过所有策略归属持仓的部分，可能是人工交易、别的系统持仓或 QMT 模拟成交/持仓不一致；它不是自动卖出清单。先决定这些持仓保留、卖出，还是由专门的持仓迁移流程归属，不能伪造账本成交。还要确认实际可用资金足够新分配的 `QMT_INITIAL_CAPITAL`。
4. 若只有 GoodETF 使用该数据库，可以用**新的数据库路径**冷启动，并给本轮策略一个新的 `STRATEGY_ID`（如带启动日期的 ID）。在聚宽策略顶部、私有 `jq_runtime_config.py` 的 `STRATEGIES` key、服务器白名单 `QMT_STRATEGY_ENABLED_IDS` 三处使用同一新 ID。QMT 初始资金仍由策略顶部 `QMT_INITIAL_CAPITAL` 指定。旧数据库和旧 ID 保留归档。
5. 如果同一数据库还承载其他策略，不能换掉整库，也不能简单改 ID：旧账户仍占用资金。需要先设计并验证旧策略停止、持仓交接和资金释放，再创建新账本；当前没有可安全“一键重置单个 ID”的命令。
6. 只开只读，检查新账本绑定的 QMT 账号、资金和物理持仓，再单独批准恢复策略交易。

## 模拟账户切换到真实资金账户

不要在原账本里把 QMT 账号或 `QMT_ACCOUNT_ID` 改为实盘账号，也不要复用旧的能力证明。实盘必须使用独立的策略 ID、独立数据库路径、对应实盘账号的新能力验证结果。大 QMT 桥接每个服务实例只接一个 STOCK 物理账户；若要模拟盘与实盘同时运行，需两个隔离的服务实例、端口、桥接及数据目录，不能让两个实例消费同一策略信号并指向同一资金账户。

迁移前先停旧实例策略交易、核对未完成委托和持仓、完整备份。新实例保持交易关闭，验证实际登录账户、桥接连接、行情、账户资金、能力证明、策略白名单和初始资金分配。聚宽私有配置指向新实例，并使用新的 `STRATEGY_ID`；先只读预检，再进行单独授权的最小实盘验收。**换 ID 或新建数据库不会自动清理旧 QMT 持仓，也不能证明旧成交真的完成。**

## 本次对账修复的边界

服务器每轮对账记录 `unassigned_broker_positions`，并在变化时记日志；它不会把多余的 QMT 持仓自动归属给 GoodETF，也不会自动卖出。大 QMT 桥接保留原生成交金额；若成交价与券商成交金额折算单价明显冲突，以成交金额核算并记录差异。若两者都缺失或都异常，无法仅靠策略参考价恢复真实成交价格，必须核对券商原始回报及持仓。QMT 市价单传入的 `price` 参数不是成交价格上限或下限。
