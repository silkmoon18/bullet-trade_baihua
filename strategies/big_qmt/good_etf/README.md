# 独立大 QMT GoodETF

`good_etf.py` 是可整份复制到完整 QMT 策略编辑器的单文件。它直接使用 QMT 内置行情、账户、`passorder`、委托和成交回报，不连接聚宽、BulletTrade 服务器、bridge 或 miniQMT。配置集中在脚本顶部。

本目录不替换现有 `strategies/joinquant/good_etf.py`、旧 `strategies/qmt/good_etf/`、服务器或 bridge。按2026-10-15用户最新授权，当前顶部已设置`ENABLE_TRADING=True`、`PAPER_TRADING=False`、`INITIAL_CAPITAL=1000.0`，会实际向QMT绑定的账户提交委托，不再是纸面模拟。绑定实盘账户就是真实资金交易，绑定模拟账户就是模拟柜台委托；本文件不自动切换账户。策略ID为`good_etf_big_qmt`。

策略账本只管理自身归属持仓，不认领或卖出其他策略/人工持仓，也不修改服务器的5000元账本。已有原生账本照常恢复，不能改初始资金或删除文件来重置；此前只有纸面模式时没有真实账本可继承。1000元按100份整手分配，部分标的可能不足一手，未必买齐3只。

## 当前实际下单及耗时验证

只更新本目录单文件`good_etf.py`（GBK），完整替换QMT编辑器代码。先暂停同账户会并发下单的旧自动策略，再在QMT策略交易界面选择账户（或仅在客户端填写`ACCOUNT_ID`），以1分钟周期运行。无需修改聚宽、helper、私有config、服务器或bridge；这次本地修改没有替用户启动或提交任何委托。

```python
ENABLE_TRADING = True
PAPER_TRADING = False
INITIAL_CAPITAL = 1000.0
```

决策仍为09:20准备、09:30选股下单，保留原选股、定价、先卖后买、回报入账及风控行为。实盘默认`ALLOW_UNDATED_LIVE_NAV=True`：优先使用QMT的有效正数`nav`，`preTradingDay`/`tradingDay`为0、空或缺失时提示“日期未核验”，不再仅因此拦截或强制填写`NAV_FILE`。任何已返回的明确日期与目标前日/当日不符仍排除该QMT记录；无效净值不能用IOPV替代。需要恢复严格日期校验时设为False。**此规则只改变独立大QMT实盘的数据缺失处理，不修改历史回测或现有JQ/服务器。**

日期缺失时，接口无法证明PCF已更新。每天运行前请通过QMT“数据管理 → ETF申赎清单”下载/更新当日数据，这是QMT自身的数据，不是准备外部文件。脚本保留原始日期及读取时间，明确不把读取时间当成净值日期；不会把确认更新的任务伪装成自动通过。入选标的的`入选净值`日志在发单接口调用后输出，含代码/名称、nav、原始两日期和核验状态，不拖慢首笔发单。

日志`实单耗时`记录计划时间、实际回调时间、定时触发延后、定时查询、行情读取、选股、目标准备（含账户查询/估值/落盘）、首笔`passorder`调用时间及回调至首笔耗时。每笔`下单请求`另记录接口调用/返回的毫秒时间及调用耗时，接口返回不代表委托已接受或成交。

日志`执行回报耗时`关联原委托，分别标注`来源=回调`或`来源=查询`，记录本地观察时间、券商原始委托/成交时间、提交至该次观察的耗时和累计成交。查询结果的观察延迟包含查询间隔，不能冒充纯回调/撮合延迟；同进程使用单调时钟计时，重启前订单的耗时记未知，不把不同进程的时钟相减。时间字段对应[迅投委托及成交结构](https://dict.thinktrader.net/innerApi/data_structure.html)中的`m_strInsertTime`、`m_strTradeTime`，未提供则显示未提供。

`执行链路耗时`进一步汇总各QMT原生接口的调用次数、累计/最大毫秒数及异常数，覆盖日历、ETF板块、合约、日线、PCF、tick、资金/持仓/委托/成交、passorder/cancel。`local.select_rank_weights`是本地排序权重，`local.ledger_*`拆分JSON写入、flush/fsync和原子替换，`local.log_stdout_and_file`是输出开销；`phase.*`为包含子调用的完整阶段，不能和子阶段相加。正常报价和下单逻辑不变，不为计时额外查询或发单。重复PCF读取聚合、不每秒刷空闲日志；有实际接口/落盘活动的timer与成交回报会输出到同一UTF-8本地日志。QMT接口内部的缓存/行情网络/柜台网络只能算在接口总耗时内，不能声称已分别测得。

## 可选纸面下单时间与耗时

若要退回不发单的纸面观察，停止脚本后在顶部明确改为以下配置，再启动：

```python
ENABLE_TRADING = False
PAPER_TRADING = True
PAPER_INITIAL_CAPITAL = 5000.0
```

09:30选股完成后立即在内存计算虚拟目标，先模拟卖计划外及超额部分，再模拟买入；保留计划内需要的份额，参考价上浮0.2%的固定买入限价仍复用原计算。卖单未假设成交时不模拟买入。全程没有`passorder`、账户查询或飞书调用，原交易路径和选股公式不变。

日志`纸面下单`包含标的代码/名称、方向、数量、单价、金额、纸面下单毫秒时间、回调至下单耗时及假设成交状态。`纸面耗时`包含计划时间、实际回调时间、定时触发延后、行情读取耗时、选股计算耗时、目标计算、首笔纸面下单时间和耗时。首笔纸面时间在输出选股明细及写日志前采样，避免把批量日志耗时误算成决策必需时间。

这是本地纸面请求，不是QMT模拟账户的委托；不存在柜台委托/成交回报，不能测真实网络、柜台和撮合延迟。用最近一次有效`lastPrice`，只在价格符合委托条件时假设立即全额成交；不模拟盘口深度、排队、部分成交、费用、T+1、止盈止损或未成交续单。14:55仅输出虚拟现金和持仓，不作为收益报告。未核验PCF仍标为未核验，不能把纸面结果当作实盘数据验收。

## 启动

1. 在 QMT 数据管理中补充全市场 ETF 日线，并保持更新。核对客户端板块名称与 `ETF_SECTOR` 一致，不使用只有自选ETF的板块代替全市场。
2. 用 GBK 编码打开 `good_etf.py`，整份复制到 QMT 的新 Python 策略中保存。文件本身以GBK保存并有匹配的编码声明。
3. 当前实际下单配置为`ENABLE_TRADING=True`、`PAPER_TRADING=False`、`INITIAL_CAPITAL=1000`。在策略交易界面绑定确认的账户，或在本机填写`ACCOUNT_ID`，使用1分钟周期启动。不要在没有绑定账户时直接点击编辑器运行；不要只改QMT界面的资金，忽略本脚本的归属资金配置。
4. 在QMT数据管理中下载/更新ETF申赎清单和全市场ETF前日日线，在09:20前启动。09:20准备候选，09:30读取开盘后 `lastPrice` 输出选股；错过09:30不会补选历史时点。回调开始、行情读取开始、计算完成、行情及选股耗时、最后行情时间都会记录；便于与聚宽的采样时点区分。
5. 核对`实单耗时`、`下单请求`、`执行回报耗时`、`入选净值`及QMT委托/成交列表；同时核对标的、数量、价格、资金和策略归属持仓。实盘允许日期缺失的净值，但会标记未核验，不代表已确认更新到前一交易日。

确认选股数据一致不等于验证实盘成交。实际运行前需确认净值日期、账户、资金、行情和券商下单回报。不得与旧策略同时交易同一账户；不要拷贝旧账本或提交账户/凭据。脚本初始资金控制本策略的分配，不代表更改证券账户总资金，也不保证无手续费、滑点或交易损失。

必须停用的只有同账户、可能并发交易的旧策略；本文件不会替你停服务器或切换账户。观察模式可以与原服务并存。运行模式显示“实盘”不代表账户一定是真实资金账户，账户身份需在客户端确认。

### 复制保存乱码

运行所需的中文字符串（含`ETF_SECTOR`板块名、港股过滤关键词、日志和通知）使用Python的`\uXXXX`转义保存，运行时仍是原来的中文，避免复制/保存时被替换成`?`而改变数据查询或过滤。中文注释保持可读，配置含义不变；例如`ETF_SECTOR`的转义值仍为“沪深ETF”，不要替换为问号。契约测试比较原始源码与中文被替换后的整棵语法树，保证除了注释，执行内容完全一致。

若QMT窗口和账本旁的UTF-8日志都出现问号，损坏已发生在源码复制/保存或编译入口，单改日志输出编码无法恢复。停止该脚本后，用本目录完整文件替换，保留原账户、ID、资金和账本目录；不要删除账本或换ID重跑。若已有委托，停止脚本不等于撤单，须先核实原委托状态。此步骤不修改JQ策略、helper、服务器或bridge。

## 前日单位净值

GoodETF使用前一交易日的单位净值，不使用实时IOPV。实时路径依次尝试：

- 优先读取大QMT内置`get_etf_info(code)`的`nav`。两个日期均明确匹配则记日期已核验；实盘默认允许缺失日期，但保留未核验标记。只允许“日期缺失”降级，不允许忽略明确错误日期。
- 只有QMT缺失的标的才读顶部 `NAV_FILE` 指向的本地JSON，其 `date` 必须是前一交易日；文件不会覆盖有效QMT净值。QMT覆盖完整时不读取文件。

示例结构（示例数值不能用于交易）：

```json
{
  "date": "20261013",
  "nav": {"510300.SH": 4.1234, "159225.SZ": 1.2345}
}
```

部分缺失/无效/明确日期不符会列出样例，未被可选文件补充的ETF按原inner join排除。全部缺失则保留原持仓、不创建清仓计划，日志明确提示。PCF权限不足或无有效净值时，可选提供每日更新的前日净值文件；仅日期字段为空不要求外部文件。这个单文件不能解除券商数据权限，也没有假设无VIP一定能取得PCF。

仅选股/纸面路径也允许PCF日期缺失时读取有效`nav`，每只入选标的明确标注未核验。净值为0/负数/缺失/非有限数仍排除，不以其他行情价代替。历史回测始终要求历史日期正确，实盘`ALLOW_UNDATED_LIVE_NAV`不能放宽回测，也不会把当前PCF伪装成历史净值。

实现及边界依据：[迅投内置行情函数](https://dict.thinktrader.net/innerApi/data_function.html)描述PCF每日盘前更新，其示例的日期字段也可为空；[迅投上手说明](https://dict.thinktrader.net/freshman/rookie.html)列明内置接口的数据通过界面“数据管理 → ETF申赎清单”下载。文档未提供可在日期缺失时证明当日已更新的返回字段，因此日志保持未核验，不根据数值没变或读取成功推断新鲜度。

原生板块、基金简称、跟踪指数和PCF覆盖可能与聚宽不同。`TRACKED_INDEX_NAMES` 可补充跟踪指数名称，港股过滤保留原有名称、指数关键词及明确代码兜底，不按513前缀排除所有海外ETF。相同输入的过滤、排序、精确权重已由契约测试与当前聚宽GoodETF对比；不能承诺不同数据源每天选中同样标的。

## 默认决策与执行

- 09:20：前一交易日ETF池、港股过滤、前日成交额严格大于500万且小于2000万、前日单位净值。
- 09:30：读取有效的开盘后`lastPrice`，排除停牌和涨停，计算`(最新价/前日单位净值-1)*100`，取折价最深的3只。按绝对折价归一化，权重合计95%。这不是09:26开盘价实验。
- 目标份额：策略账本权益乘权重，按参考价折成100份整数手，保留仍需要的已有持仓。
- 先处理计划外和超额持仓。卖出委托终结且成交入账后，再买入。资金分别受策略账本余额、真实可用资金和在途买单预留约束。
- 买入：决策时`lastPrice`上浮0.2%，按ETF价格跳动向下取整并受真实涨跌停价约束，直接挂固定限价。有效委托一直等待，不因行情波动撤掉改价，不做价格笼子等待。
- 调仓卖出和止损：默认沪市原生42、深市原生47五档即成剩撤。沪市传1.5%保护价。深市47的`price`不具有相同保护语义，不宣称深市也有该保护线。已撤且部分成交入账后才对实际余量续单，不对未知提交重发。
- 止盈：触发价下浮0.2%的固定限价。止盈/止损分别为相对策略平均成本严格高于110%、低于95%。T+1可卖数量为0就等待，不伪造卖出。
- 废单：报告原因，不因类型不支持或余额不足自动更换价格类型。模拟柜台不支持42/47时，可明确将对应 `SH_NATIVE_MARKET`/`SZ_NATIVE_MARKET` 设为False，退化为保护价固定限价；其行为与市价不同。
- 10:30、13:30、14:50：风控。14:55：策略权益、净值、已知费用、未知费用笔数、估算成交笔数及最后行情时间。目标仅当天有效，跨日不继续买旧计划；午夜/重启查询旧委托并尝试撤单，未知委托不当作已撤。

实时行情零值或非当天行情不会参与选股。正常成交直接用券商回报价和成交金额，不为正常回报查询价格。异常成交价/金额才查询有效最新行情入账，保留原回报并标注估算；费用缺失记未知。存在估算或未知费用时，快照明确标注“非精确收益”。行情兜底只供已确认成交的记账，不拿来伪造成交数量或回报。

本地账本旁保存每日UTF-8日志。QMT策略日志同样输出，飞书由顶部 `FEISHU_WEBHOOK` 控制。卡片含策略ID；单标的卡片标题包含代码和名称，数量、单价、金额等字段各自一行。

## 重启与账本

同一天重启沿用原账本和已完成调度记录，不重复选股下单。已发送但尚未明确终结的委托先查询认领，不自动重发。`stop`只释放本地锁，不撤销柜台委托；重启后接着核对。

更换模拟/真实客户端时分别使用独立ID及账本目录。已有成交不能靠修改 `INITIAL_CAPITAL`、删除账本或改ID绕过；重新开始前应先停止策略并确认原委托、策略持仓已处理。

## QMT原生回测

自动识别 `ContextInfo.do_back_test`，不绑定柜台账户，不创建实时账本，不调用实时`passorder`。资金、费用、滑点取QMT回测面板，使用1分钟周期、不复权。

默认 `BACKTEST_DATA_FILE=""`，不再强制先准备外部数据。回测也先尝试QMT：

1. 用 `get_stock_list_in_sector(ETF_SECTOR, 前日末毫秒时间戳)` 请求历史板块成员，合约资料用于上市/退市日期和名称。名称仍取客户端资料，不承诺恢复历史更名；不支持历史成员参数时不偷偷改用今日ETF池。
2. 在历史bar对应的当天调用内置 `get_etf_info(code)`，只有 `preTradingDay` / `tradingDay` 明确匹配本次历史前日/当日才接受 `nav`。这是对客户端能力的实际尝试：官方仅说明PCF每日盘前更新，没有确认它会随回测日期重放。返回最新PCF、日期为空或无权限时，日志打印期望日期、返回日期和有效覆盖；不能由此得出有效历史回测收益。
3. 行情、成交额、已完成分钟线仍取QMT；历史涨停价尝试 `get_market_data_ex([], codes, period="stoppricedata", ...)`，只接受本次历史当天且不晚于当前bar的记录。该特色数据的内置兼容性、ETF覆盖和权限需在客户端验证；不按固定10%猜测涨停价，也不用今日合约涨停价回测历史。

QMT所需数据都有效就直接回测。缺失时可选填写 `BACKTEST_DATA_FILE`，作为历史每日ETF池、前日单位净值、当日涨停价的补缺来源；明确日志标出使用文件的位置。若QMT和文件均缺失，回测停止并说明原因，不伪造历史数据。已有文件格式继续兼容，结构如下：

```json
{
  "schema": 1,
  "sessions": {
    "20261014": {
      "previous_date": "20261013",
      "securities": {
        "510300.SH": {"name": "示例ETF", "index_name": "沪深300", "nav": 4.1234, "high_limit": 4.5}
      }
    }
  }
}
```

回测使用已完成分钟线。若09:30没有完整bar，等09:31第一根完整bar再决策。回测只提交原生目标市值，不模拟实时追单，因此不把该结果宣称为聚宽09:30开盘价撮合的完全复刻。

### 不用外部文件的首次验证

只更新本目录的 `good_etf.py`，整份复制到QMT。顶部暂时保持 `NAV_FILE=""`、`BACKTEST_DATA_FILE=""`、`ENABLE_TRADING=False`。客户端补充全市场ETF日线、分钟线、ETF申赎清单，回测选择1分钟、不复权，先用较短区间。

把首次回测的 `QMT历史ETF池`、`QMT净值接口`、`QMT历史涨停价` 和报错发回即可判断实际客户端支持什么。实时观察也打印同一净值接口覆盖，不会因测试数据接口自动开放交易。若回测在净值阶段停止，后续行情/涨停价阶段尚未验证，不能宣称已全部通过。本改动不涉及旧聚宽helper、原服务或bridge。
