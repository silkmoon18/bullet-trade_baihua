## 明确的交易规则

1. 默认池为6只国内宽基ETF及6只行业ETF。用`context.previous_date`的ETF上市名单过滤，自上市起至少120个自然日；历史窗口不足则排除。固定研究池仍有池子选择偏差，需要单独做宽基池对照。
2. 因子数据明确截止上一交易日：使用前复权日线，保留停牌日期；昨日停牌的标的排除。近20交易日日均成交额至少2000万元。
3. 昨日收盘价严格高于60日简单均线；最近5个交易日收盘到收盘的收益率不高于-3%。计算公式为`close[-1] / close[-6] - 1`。
4. 按5日收益率从低到高排序，相同跌幅按证券代码升序。在09:35读取当前快照，排除停牌、无效报价、涨跌停标的，然后取前3只。当前价格仅用于可交易过滤及委托参考，不参与跌幅或趋势计算。
5. 每个名额目标权重固定为`0.90 / 3`。入选1只时部署30%，2只60%，3只90%；其余保留现金。无信号时提交空仓目标。
6. 从2010-01-04起按聚宽交易日历计数，每5个交易日重新选股并调仓。中间交易日不提交目标。连续入选可以继续持有，所以5日是**目标轮换周期**，并非每笔成交严格持有5日；换池、卖出失败或停牌也会影响实际持有时间。可将`HOLD_DAYS`改为3或10对照。
7. 基线没有盘中止盈止损，也不会在刚买入后同日发止损。退出由下一轮目标决定，因此轮换间的下跌风险仍然存在。

数据读取异常、缺失、过期或包含越界日期时跳过整轮，不会把失败解释成空仓，也不沿用旧信号。正常无信号则明确退出，二者语义不同。

## 在聚宽试跑

用仓库解释器执行：

```bash
python scripts/export_joinquant.py --strategy etf_reversal --output dist/joinquant-etf-reversal
```

将导出的`bullet_trade_jq_remote_helper.py`上传到**聚宽研究根目录**，将`etf_reversal.py`粘贴到新的聚宽策略。helper必须为API23。回测默认关闭远程预检，**不需要私有配置文件、服务器或QMT连接**；导出的配置模板用于以后配置模拟账户，不需要为本次回测填入凭据。模拟盘则沿用现有私有配置规则，新策略身份为`etf_reversal_daily`。

平台参数由现有helper统一设置：沪深300基准、真实价格、避免未来数据、基金买卖佣金各0.00025、最低佣金5元、`FixedSlippage(0.002)`。这里的滑点是固定价格差参数，不能当成0.2%。JQ沿用原生委托和撮合，不等待全部卖出后再买，不添加分钟补单。

建议先用10万元、分钟回测、2019-01-01至2026-09-30的完整区间，另看2022、2024及2025-2026的分段表现。当前参数没有使用该区间优化，但该区间也不能声称为严格预注册的样本外验证。

## 延迟实验

固定`OPEN_DECISION_TIME = '09:35'`，仅改变下单时间：

| 下单时间 | 延迟 |
|---|---:|
| `09:35` | 0分钟 |
| `09:36` | 1分钟 |
| `09:40` | 5分钟 |
| `09:50` | 15分钟 |

helper冻结当日选中的代码、权重、参考价和JQ定额基数，下单时不重新排名。各次完整回测仍会因先前成交差异而走出不同资金路径。延迟整轮调仓同时影响减仓和买入；这是分钟级实验，不能据此推断秒级延迟。

先完成4组延迟对照，再一次只改变一个维度：`REVERSAL_DAYS=3/5`、`TREND_DAYS=60/120/200`、`HOLD_DAYS=3/5/10`；ETF池另做仅前6只宽基的对照。比较年化、最大回撤、交易次数、费用和各年度收益，关注不同延迟的差距是否缩小。减少对开盘瞬间报价的依赖是本版本的设计目标，是否有效仍需这些回测结果验证。
